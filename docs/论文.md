# 星球物理模拟器：基于客户端补算架构的 Web 端 N 体引力沙盒

## 摘要

本文介绍了一个运行于浏览器的二维 N 体引力沙盒系统「星球物理模拟器」。系统以「单服务器权威物理 + 客户端补算」为核心架构：服务器以 30Hz 运行权威模拟并以 12Hz 推送二进制状态帧，客户端维护一份镜像模拟，在权威帧之间进行本地积分以获得 60fps 的平滑画面，并在权威帧到达时进行状态对账。物理层面，系统实现了 Paczyński–Wiita 伪牛顿势下的黑洞引力（含最内稳定圆轨道、事件视界捕获与引力时间膨胀）、KDK 蛙跳积分与自适应子步、碰撞的四种结局（并合、反弹、潮汐撕碎、超临界碎裂），以及由质量段与「吞并 + 岁月」双驱动的恒星生命周期。系统同时提供了类 Minecraft 的世界管理模式（本地存档、对局域网开放、房主语义）与完整的工程可靠性设施（输入校验、单包崩溃防护、房间上限与限速）。经单元测试与端到端冒烟测试验证，系统在普通笔记本浏览器中可稳定运行于 120FPS。

**关键词**：N 体模拟；客户端补算；伪牛顿势；WebSocket；权威状态对账

## 1 引言

引力 N 体模拟是天文学教学与公众科普的经典载体，但现有工具要么是桌面专业软件（上手门槛高），要么是单机网页玩具（无法多人共享）。本项目的目标是构建一个「打开网页即玩、朋友输入房号即联机」的引力沙盒，同时保证物理表现的可信度：黑洞要有视界与时间膨胀，恒星要有生命周期，碰撞要有碎裂与弹跳而非全部无声合并。

实现上有两个核心矛盾需要解决：其一，权威物理放在服务器则帧率受限，放在客户端则多人状态无法一致；其二，物理真实性（吸引子、并发事件、长时间演化）与浏览器性能之间互相制约。本文的架构设计与关键技术即围绕这两个矛盾展开。

## 2 总体架构

系统采用前后端一体化的单服务交付：Node.js 进程同时托管静态网页、权威物理模拟与 WebSocket 服务，部署仅需一条命令。

**服务器为物理权威**。每个联机房间持有一份独立的 `Simulation` 实例，以 30Hz 执行物理步进，并以 12Hz 将全部天体的位置、速度、质量编码为二进制帧广播（相比 JSON，体积缩小约一个数量级）。控制指令（生成、拖拽、推进、投票等）以 JSON 上行，服务器校验后应用于权威状态。

**客户端为渲染与输入**。浏览器维护一份「镜像模拟」，在两次权威帧之间以引擎的镜像模式（mirror）本地积分：只计算引力、推进与轨迹，不判定碰撞与生命周期——这些由服务器权威裁决，避免双侧分歧。镜像积分使画面在 12Hz 帧间依然平滑；当权威帧到达时，对每个天体做对账纠偏：偏差小于阈值时按比例软收敛，偏差过大（并合重组、拖拽瞬移）直接对齐，玩家正在抓取的天体与自己的飞船只做软纠正以保证手感。

**离线兜底**。连接不可用时，同一套引擎自动切换为本地单机权威，配以「预演缓冲」（影子模拟超前推演、逐帧消费）实现飞船轨迹预测线；重新连接后无缝回到联机。

## 3 关键技术

### 3.1 数值积分

主体采用 KDK 蛙跳积分（踢-漂-踢），能量长期行为好。子步数自适应：以场景中最紧密轨道（卫星绕宿主）的周期为基准，保证每圈不少于约 150 个积分步，防止近距小轨道数值发散；子步上限按场景规模分档（小场景 6 步、大星系 2 步）。碰撞检测在每个物理子步后执行——高速天体一帧可跨越数个身位，帧末检测会穿透或错过真实撞击点。近黑洞区域另设「护盾」：任何天体进入 3 倍视界半径即按局部动力学时标追加细分步，避免大步长跨过视界后被发散引力甩飞。

### 3.2 黑洞与伪牛顿势

史瓦西黑洞的引力采用 Paczyński–Wiita 伪牛顿势 `a = GM/(r−r_s)²` 近似，它比牛顿势更真实地再现了最内稳定圆轨道（ISCO = 6r_s）的存在：天体进入 ISCO 内发生轨道衰减坠毁。事件视界捕获在子步两端双重检查，防止高速坠入者跨过视界后被数值误差弹飞。界面同时给出引力时间膨胀读数 `dτ/dt = √(1−r_s/r)`，使相对论效应可感可见。

### 3.3 碰撞与质量段

碰撞结局由相对速度与两体逃逸速度之比分档：超过 1.5 倍碎裂为碎片群；0.3–1.5 倍之间发生物理反弹（法向恢复系数、切向摩擦产生自旋、动能损失转化为碰撞火花的可视发光，并从接触点溅射碎屑）；低于 0.3 倍吸积并合。恢复系数按能量分级，避免了贴脸天体因引力逐步泵入能量而陷入「弹开—拉回」的数值极限环。大质量比的天体进入洛希极限被潮汐撕碎（黑洞除外——坠入视界即被吞噬）。碎裂与溅射均受碎片冷却、总量保险丝约束，防止级联雪崩。

天体类型由质量唯一决定（质量段表：小行星/卫星/行星/恒星/黑洞），并合后按新质量重新定级——卫星并合成行星、行星越过点燃线成为恒星，类型、命名与外观同步更新。

### 3.4 恒星生命周期

恒星演化由「吞并 + 岁月」双驱动：吞并直接累计吸积质量；同时恒星按质量三次方速率随模拟时间自然衰老（大质量恒星寿命短的真实规律）。外观按质量分段（红矮星/类日/蓝白巨星/超巨星），阶段跃迁伴随半径、颜色突变与爆发特效；低质量恒星终局为白矮星，大质量恒星吞并或衰老至阈值后经超新星塌缩为黑洞。时间倍率（×1–×1000）使数百万年的演化在数十秒内可见。

### 3.5 联机与世界管理

多人交互采用类 Minecraft 的管理语义：开放局域网者成为房主，暂停、回退、清空、切换预设等全局操作由房主直接执行；无主的公共大厅则由全员投票过半执行；房主退出即解散房间。天体归属与三级权限（管理/移动/只读）保护玩家的创造物。

工程可靠性方面：所有客户端数值（坐标、质量、油门）经有限性与值域校验，防止 NaN 污染权威模拟；畸形数据包（如字面量 `null`）不会导致进程崩溃；WebSocket 设有报文上限；生成操作按玩家限速并受全房天体总量熔断保护；房间数量设上限、空闲房自动回收；快照（用于时间回退）剥离轨迹数据以控制内存。

### 3.6 存档

以「存档为基础」启动：游戏每 30 秒将宇宙状态（含相机视野）自动写入浏览器 IndexedDB，下次打开自动恢复；支持多槽位保存、导出/导入 JSON 文件；联机宇宙在退出时回收至房主本地存档，实现「世界跟着人走」。

## 4 测试与验证

系统建立了两层自动化验证：15 项引擎单元测试覆盖质量段定级、并合升级、生命周期演化、碰撞三结局与存档往返；18 项端到端冒烟测试基于真实 WebSocket 协议栈，覆盖进房、帧流、生成、开房、权限（房主直通/非房主拒绝）、投票、回退、健壮性（畸形包、NaN 输入、房间接管拒绝）与特效内存有界性。渲染层通过光晕精灵缓存、暗角渐变缓存与星空视差增量累积等手段，在普通笔记本浏览器中稳定运行于 120FPS。

## 5 总结与展望

本文实现的星球物理模拟器证明了「权威服务器 + 客户端补算」架构可以在浏览器中同时交付物理可信度、多人一致性与 60fps 的流畅体验；类 Minecraft 的世界管理使联机门槛降到「发一个房号」。未来工作包括：以 Barnes–Hut 四叉树或 WASM 将可模拟天体数从千级推向万级；WebGL 渲染管线支持十万级粒子吸积盘；以及基于时间快照的「宇宙回放」教学功能。
